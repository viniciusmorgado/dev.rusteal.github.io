# The runtime

`rusteal-core` is the safe runtime: every `unsafe` call through the API table is confined to it, so the generated bindings and game code only see safe types. `rusteal-runtime` is the one crate a game depends on. This chapter is a map of both, and of the editor module that completes them on the C++ side.

## `rusteal-core`, file by file

| File | Role |
|---|---|
| `lib.rs` | Modules and re-exports; `lock_or_recover` and friends, which recover a poisoned lock instead of panicking. |
| `api.rs` | The table pointer (`static API: OnceLock`): `init_api` (the first library's table is kept; the services are the same for every library), `api()` (panics when not initialized), `is_api_initialized()`. |
| `module.rs` | `Module` (a library: crate, source root, bindings table, owned crates, expected registrations, its start and stop state), `ModuleId`, the current module (`scope`, `current`), `FuncTable` (a bindings crate's table of engine functions), `type_id` (a `const fn` FNV-1a hash). |
| `ffi_dispatch` | Generated by `build.rs`, one function per table entry (see [The Rust–C++ boundary](boundary.md)). |
| `object_ref.rs` | `UObjectRef<T>`, `Checked<T>`, casts, upcasts. |
| `weak_ptr.rs`, `soft_ref.rs`, `subclass_of.rs`, `pinned.rs` | Weak and soft references, class references, GC roots (see [Reification](reification.md#object-references)). |
| `traits.rs` | `UeClass`, `UeStruct`, `UeEnum`, `HasParent`, `Inherits`, `UeHandle`, `ValidHandle`. |
| `reify_registry.rs` | Registering a module's types, instance data, function dispatch, the registration manifest (see [Reification](reification.md)). |
| `delegate_registry.rs` | Closures bound to delegates and console commands, by id; `DelegateBinding`. |
| `dynamic_call.rs` | Calling a function, or broadcasting a delegate, by name through reflection. |
| `containers.rs` | `UeArray`, `UeMap`, `UeSet` views; `OwnedStruct<T>`. |
| `struct_ref.rs` | `UStructRef<T>` and `OutRef<T>` into parameter buffers. |
| `fname.rs` | `FName`. |
| `ue_math.rs` | `Rotator`, `Transform`, `LinearColor`, `Color`, `Plane`, `Ray`, `Sphere`, boxes and bounds, on `glam`. |
| `world.rs` | Spawning, finding, loading and creating objects, actors of a class, data table rows. |
| `console.rs`, `input.rs`, `widget.rs`, `logging.rs` | Console commands and variables, Enhanced Input binding, widgets, `ulog!`. |
| `task.rs` | Background work on the engine's tasks, dedicated engine threads (`spawn_thread`, `EngineThread`), the game-thread queue, tick hooks, `is_game_thread` (the engine's `IsInGameThread`), `worker_count`. |
| `sync.rs` | The only source of `Mutex`, `RwLock`, `Once`, `OnceLock` and `thread_local!` in `rusteal-core`, with `lock_or_recover` and friends: what a platform whose `std` lacks them would replace. |
| `executor.rs` | Async tasks on the game thread: `spawn_local`, `JoinHandle`, `AbortHandle`, `next_frame`, `run_blocking` (see below). |
| `timer.rs` | World timers with closures, `TimerHandle`, `sleep` and `sleep_real`. |
| `latent.rs` | Awaiting the engine's latent functions (`LatentCall`) and running an `async #[ufunction]` as a latent action. |
| `loading.rs` | Background loads through the asset manager's `FStreamableManager`. |
| `event.rs`, `events.rs` | `once()`, the channel behind every `next()`; native engine events (`NativeEvent`, `EventBinding`). |
| `http.rs` | HTTP requests through `FHttpModule`. |
| `method.rs` | `method(self, Self::x)` and the `RustObject` trait. |
| `time.rs` | The engine's clock (`FPlatformTime::Seconds`): `now_seconds`, `sleep`, and `Instant`, shaped like `std::time::Instant`. |
| `std_fallback.rs` | The `std` threads, clock and core count, used only when no engine is there (the unit tests). |
| `error.rs`, `ffi_guard.rs` | `RustealError` and panics (see [Errors](errors.md)). |

## Threads and ticks (`task.rs`)

The thread that runs `rusteal_init` is recorded as the game thread. Every queue below is per [module](boundary.md#the-current-library-privaterusteallibraryh): a library's `on_tick` runs its own jobs and hooks, once per frame, and its shutdown waits for its own tasks. Then:

- **`run_on_game_thread(f)`** pushes `f` onto a queue; it runs on the next tick.
- **`spawn(work, done)`** runs `work` as a task of the engine's task system (`platform.launch_task`, `UE::Tasks::Launch` at background priority), with the spawning module current there, and queues `done(value)` for that module's game-thread queue. A panicking `work` is logged on the game thread; a thread that cannot start is logged too. Running tasks are counted.
- **`spawn_thread(name, f)`** starts a dedicated engine thread (`platform.create_thread`, an `FRunnableThread`), with the module current there, for work that lasts; `join()` waits for it (`platform.join_thread`), and a dropped `EngineThread` is kept by its module and joined when the module shuts down.
- **`on_tick(f)`** registers a hook called every tick with the delta time, until its `TickHandle` (which names its module) is removed (the handle is `#[must_use]`: dropping it keeps the hook forever).
- **`tick(delta)`**, the `on_tick` callback: drains the queue, then calls the hooks, each under `catch_unwind`, without holding the lock while user code runs, so a hook may add or remove hooks.
- **`shutdown()`**, from the module's shutdown: waits for its running tasks (warning after a second), joins its dropped threads, then clears its queue and hooks, so no thread runs code that is unloaded.

- **`spawn_local(&owner, future)`** adds a task to the module's executor (`executor.rs`): `tick` polls the tasks whose waker fired, after the jobs, and drops those whose owner is gone (see [Decisions](../decisions/index.md), D24). `shutdown()` drops them before the hooks are cleared.

On the C++ side, `StartupModule` adds `TickLibraries` to the core ticker (`FTSTicker::GetCoreTicker()`), which calls every library's `on_tick` each frame.

## Calling by name (`dynamic_call.rs`)

`DynamicCall` is what the bindings do not cover: functions defined in Blueprints, a `BlueprintImplementableEvent`'s implementation, delegates.

1. `DynamicCall::new(obj, "Function")` checks the object, finds the function by reflection (`function_not_found` otherwise) and allocates its parameter buffer; `for_delegate(obj, property)` takes the delegate's signature instead.
2. `set(name, value)` finds the parameter and its offset and writes the value (an `FName` through the property, to keep its display index); `set_struct` copies a struct; `set_value` writes any `DynamicValue` (strings, texts, containers, soft and weak references) through the parameter's property.
3. `call()` runs `reflection_call_function`; `broadcast()` a multicast delegate, `execute()` a single-cast one. The result's `get(name)` reads a scalar out parameter or return value, `value(name)` any `DynamicValue`.
4. The buffer is freed when the call or its result is dropped.

The macros generate `DynamicCall`s for `BlueprintImplementableEvent` bodies and `#[udelegate]` broadcasts, logging a failure as a warning and returning a default.

## Data

- **Containers.** `UeArray<T>`, `UeMap<K, V>` and `UeSet<T>` are `Copy` views, an owner and a property: nothing is cached, each call crosses the boundary (`len`, `get`, `set`, `push`...), and `to_vec`, `bulk_iter` and `set_all` copy everything in one call, growing the buffer once when it is too small. Elements implement `ContainerElement`: primitives (raw-copyable), handles and references, `String` (length then UTF-8), `OwnedStruct<T>` (bytes).
- **Structs.** `OwnedStruct<T>` owns a buffer sized, initialized and destroyed through reflection (`new`); copies made from bytes do not destroy. `UStructRef<T>` borrows memory Unreal owns; `OutRef<T>` writes an out parameter.
- **Math.** `Rotator` is in degrees and converts to and from `DQuat` (pitch clamped at ±90°); `Transform` is a `DQuat`, a `DVec3` translation and a `DVec3` scale; `LinearColor` converts to and from `Vec4`. The engine's large world coordinates are doubles, hence the `D` types.

## Services

- **Console** (`console.rs`): `register_command(name, help, closure)` stores the closure in `delegate_registry` and registers the command, which receives its arguments and a `CommandContext` whose `world::<W>()` checks the world's handle into a typed reference; a name already registered is refused. `ConsoleVariable<T>` (`bool`, `i32`, `f32`, `String`) registers a variable and reads and writes it as text. The plugin forgets a library's commands when it unloads.
- **Input** (`input.rs`): `bind_action_closure_raw(actor, action, trigger, closure)` binds an action to a closure through `BindActionInstanceLambda`, with the value, elapsed and triggered times and the action in `RustealInputArgs`, unbound by its handle; `bind_action_raw(actor, action, trigger, "Function")` binds an Enhanced Input action to a `#[ufunction]`, whose parameters must be a prefix of `(FInputActionValue, ElapsedSeconds, TriggeredSeconds, UInputAction*)`; the actor needs an `UEnhancedInputComponent`. `should_display_touch_interface()` is the Slate check the templates use for touch controls.
- **Widgets** (`widget.rs`): `create_widget_raw(owner, class)` picks the owner as `CreateWidget` does (player controller, world, game instance).
- **Logging**: games log through the [`log`](https://docs.rs/log) crate. `rusteal-runtime/src/ue_log.rs` installs a `log::Log` when the library initializes (`init`), with `Info` as the default maximum level, and writes each record to the `LogRusteal` category: `error!` as an error, `warn!` as a warning, the rest at display level. Each dynamic library has its own `log` instance, so the game's and every plugin's loggers are independent; in a static build they share one, and the maximum level is the runtime's. Underneath, `ulog!(level, ...)` (`logging.rs`, `LOG_DISPLAY`, `LOG_WARNING`, `LOG_ERROR`) is the raw call, kept for older projects; it needs the API initialized.

## `rusteal-runtime`

What a game crate depends on, and nothing else:

- re-exports: `rusteal_core` as `runtime`, `rusteal_ffi` as `ffi`, `rusteal_ue_flags` as `ue_flags`, `glam`, the macros, and `inventory` (hidden) for the macros' registrations;
- `callbacks`: the seven callbacks' bodies, each entering the module and running in `ffi_boundary`;
- `init(module, callbacks, table)` and `shutdown(module)`: the start and stop described in [The Rust–C++ boundary](boundary.md);
- `entry!()` / `entry!(bindings_crate)`: the library's `__RUSTEAL_MODULE`, its `__RUSTEAL_EXPORTS` (with the callbacks), and in a dynamic library the four exports;
- `on_load!(function)`: a hook run at the end of every `init` of the library that owns the crate, hot reloads included;
- `static_modules!` and `manifest()`: what a static build is made of (see [Static linking](boundary.md#static-linking));
- `rayon` (feature `rayon`): `ThreadPool`, a `rayon` pool whose spawn handler starts each worker with `task::spawn_thread`, so they are engine threads; `pool()` and `install(op)`, one pool per module, created on first use with `task::worker_count()` threads, and dropped (its workers joined) by the module's shutdown, after its tasks, which a hot reload needs; `prelude`, `rayon`'s;
- the `static-link` feature, which only the static build enables, and `engine-allocator`, which adds `EngineAllocator` (a `GlobalAlloc` over the engine's `FMemory`, through `rusteal_engine_malloc`, `_malloc_zeroed`, `_realloc` and `_free`, which the plugin defines in static builds);
- `prelude`: the references, containers, structs, errors, math types, handles, `uclass`/`uclass_impl`/`ustruct` and the `glam` types a game uses most. `uenum`, `ulog!`, `bail!`, `ensure!` and `task` are reached through the crate (`rusteal_runtime::runtime::ulog`).

The engine's types are not here: they come from the project's own bindings crate.

## The editor module (`ue_plugin/Rusteal/Source/RustealEditor/`)

`Rusteal.uplugin` declares `RustealEditor` as an `Editor` module: it depends on editor-only modules (`UnrealEd`, `BlueprintGraph`, `DirectoryWatcher`, `MessageLog`, `EditorSubsystem`), which a game target cannot link, so the runtime module stays free of them and exposes plain hooks the editor module fills in (`RustealSetClassReinstancer`, `RustealSetSourceOpener`). Its `StartupModule`:

1. registers the **Rusteal** Message Log listing (filters, no pages, clearable);
2. sets the **source opener**: `FSourceCodeNavigation::OpenSourceFile(file, line, column)`, or the default application;
3. sets the **class reinstancer** (see [Hot reload](hot_reload.md));
4. starts the **auto reload**.

It also declares `URustealEditorSubsystem`, the native parent of Rust editor subsystems, which the `editor` plugin template derives from. `ShutdownModule` undoes all four.

## Testing the runtime

There is no test double of the API table: a test that reaches `ffi_dispatch` panics in `api()`. The unit tests (inline `#[cfg(test)]` modules) exercise the code paths that do not need the engine, and the runtime keeps those paths separate on purpose (`is_api_initialized()` guards):

| File | Tests |
|---|---|
| `error.rs` | Codes, formatting, contexts, locations, std conversions, `bail!`/`ensure!`, source paths, size and `Send`/`Sync`. |
| `ffi_guard.rs` | A panic returns the default. |
| `task.rs` | `spawn`, `on_tick`, removal, `shutdown`, driven by calling `tick()` by hand; two modules ticking and shutting down apart; threads joined, or joined by the shutdown. |
| `rusteal-runtime/src/rayon.rs` | Work on a module's pool, its workers in the module, the pool dropped at shutdown. |
| `time.rs` | `Instant` arithmetic. |
| `tests/engine_services.rs` | No source file but `std_fallback.rs` uses `std::thread` or the `std` clock, and none but `sync.rs` takes locks or thread-locals from `std`. |
| `module.rs` | Scopes, ownership, the start and stop states, qualified type ids, a function table refusing other wrappers. |
| `delegate_registry.rs` | A module's shutdown clears only its closures. |
| `console.rs` | Value parsing. |
| `ue_math.rs` | Rotator and color conversions. |
| `subclass_of.rs` | Hand-written `UeClass` probes. |
| `reify_registry.rs` | Shape combination, the dependency order, two modules' instance data and functions, missing registrations. |

What needs the engine is tested in a project (see [Testing a change](../contributing/testing.md)). CI runs `cargo build --workspace`, `cargo test --workspace` and `cargo clippy --workspace --all-targets --no-deps -- -D warnings`, all without Unreal.
